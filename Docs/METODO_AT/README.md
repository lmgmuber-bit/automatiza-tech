# Método AutomatizaTech — Índice operativo

Versión: 1.0  
Fecha: 2026-07-10  
Autoridad: Luis Miguel

Esta carpeta documenta cómo AutomatizaTech diagnostica, propone, ejecuta, entrega y soporta soluciones para sus clientes. Es la fuente canónica de producto/servicio y complementa la documentación técnica en `Docs/MASTER/`.

## Documentos

- [Aplicación del Método AT](./APLICACION_DEL_METODO_AT.md): recorrido común del cliente, seis pasos, roles, gates y soporte.
- [Servicios y casos de uso](./SERVICIOS_Y_CASOS_DE_USO.md): catálogo de servicios, selección de solución, ejemplos, entregables, métricas y diagramas.
- [Flujo cliente end-to-end](../FLUJO_CLIENTE_END_TO_END.md): inventario histórico de capacidades existentes, faltantes y automatizaciones propuestas.
- [Prompt final de Claude Orquestador](../ORCHESTRATION/CLAUDE_ORCHESTRATOR_PROMPT_FINAL.md): contexto autónomo para iniciar o recuperar al orquestador principal.

## Cuándo leer

- Antes de diagnosticar o cotizar un cliente.
- Antes de crear una propuesta Gamma o blueprint.
- Al dividir un proyecto en fases/hitos.
- Cuando otro agente retoma una tarea comercial o de entrega.
- Al diseñar el seguimiento en tablero, Portal o vault.

## Regla de uso

El Método AT decide el **qué y para qué** del trabajo con clientes. `Docs/ENGINEERING_STANDARDS/` decide **cómo ejecutar profesionalmente**. `Docs/ORCHESTRATION/` decide **quién planifica, ejecuta, revisa o retoma**. `Docs/MASTER/` describe **cómo está construido técnicamente el ecosistema actual**.

## Estado actual versus objetivo

Los diagramas describen el modelo operativo objetivo de AT. Algunas capacidades ya existen —leads, citas, propuestas, contratos, Portal omnicanal, bots y tickets— y otras siguen como evolución —timeline completo de proyecto, milestones, aprobación QA y SLA automatizado—. Cada propuesta debe distinguir claramente lo disponible hoy de lo que requiere desarrollo.
